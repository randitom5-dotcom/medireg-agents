# 外包团队接口对接说明

本文档说明外包前端或外部系统应如何对接本项目。外包团队只对接 `/api/v1` 接口，不直接访问 RAGFlow、MySQL、Redis、LLM 或对象存储。

## 1. 基础约定

接口前缀：

```text
/api/v1
```

用户私有数据隔离请求头：

```text
X-Workspace-Id: reg-team
X-User-Id: alice
```

所有任务、文档和报告接口都应携带这两个请求头。当前开发版如果不传，会使用 `default / anonymous`，生产环境会改为从登录 Token 中解析，前端不允许用户自行伪造身份。

统一响应格式：

```json
{
  "success": true,
  "code": "OK",
  "message": "ok",
  "data": {}
}
```

任务 ID 与旧版 `thread_id` 兼容。前端可以不传 `thread_id`，后端会自动生成。

## 2. 健康检查

```text
GET /api/v1/health
```

用途：检查中间层服务是否可用。

## 3. 问答任务

创建问答任务：

```text
POST /api/v1/tasks/qa
```

请求体：

```json
{
  "query": "二类医疗器械首次注册需要准备哪些资料？",
  "thread_id": null,
  "dataset_ids": [],
  "metadata": {}
}
```

返回：

```json
{
  "success": true,
  "code": "OK",
  "message": "task created",
  "data": {
    "task_id": "uuid",
    "thread_id": "uuid",
    "task_type": "qa",
    "status": "queued",
    "query": "二类医疗器械首次注册需要准备哪些资料？",
    "created_at": "2026-05-26T00:00:00+00:00",
    "updated_at": "2026-05-26T00:00:00+00:00",
    "error": null
  }
}
```

查询任务状态：

```text
GET /api/v1/tasks/{task_id}
```

查询任务结果：

```text
GET /api/v1/tasks/{task_id}/result
```

取消任务：

```text
POST /api/v1/tasks/{task_id}/cancel
```

## 4. 报告任务

创建报告任务：

```text
POST /api/v1/tasks/report
```

请求体：

```json
{
  "query": "生成一份有源医疗器械注册申报资料清单分析报告",
  "thread_id": null,
  "dataset_ids": [],
  "metadata": {}
}
```

报告任务同样通过任务状态和结果接口查询。

## 5. 任务事件流

WebSocket 地址：

```text
WS /api/v1/tasks/{task_id}/events
```

外包前端应展示以下事件：

| 事件 | 含义 |
| --- | --- |
| `task_status` | 当前任务状态 |
| `monitor_event` | 后端智能体执行事件 |
| `tool_start` | 工具开始调用 |
| `assistant_call` | 子智能体开始调用 |
| `task_result` | 任务结果 |
| `task_cancelled` | 任务取消 |
| `pong` | 心跳响应 |

## 6. 文档接口

上传文档：

```text
POST /api/v1/documents/upload
```

表单字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `files` | file[] | 是 | 一个或多个文件 |
| `thread_id` | string | 否 | 关联任务或会话 |

请求头：

```text
X-Workspace-Id: reg-team
X-User-Id: alice
```

文件会保存到用户私有空间：

```text
updated/workspaces/{workspace_id}/users/{user_id}/session_{thread_id}/
```

支持文件类型：

```text
.pdf, .doc, .docx, .xls, .xlsx, .csv, .txt, .md, .json, .png, .jpg, .jpeg
```

查询文档列表：

```text
GET /api/v1/documents
GET /api/v1/documents?thread_id={thread_id}
```

文档列表只返回当前请求头对应用户空间下的文件。

查询单个文档：

```text
GET /api/v1/documents/{doc_id}
```

当前版本先保存到本地会话目录，后续会接入 RAGFlow 文档入库和解析状态。

## 7. 知识库接口

查询可用知识库：

```text
GET /api/v1/datasets
```

当前接口会优先读取 RAGFlow dataset；如果 SDK 不支持 dataset 列表，则回退读取 RAGFlow chat 列表。

## 8. 报告接口

查询报告列表：

```text
GET /api/v1/reports
GET /api/v1/reports?thread_id={thread_id}
```

查询报告信息：

```text
GET /api/v1/reports/{report_id}
```

下载报告：

```text
GET /api/v1/reports/{report_id}/download
```

## 9. 状态枚举

任务状态：

| 状态 | 含义 |
| --- | --- |
| `created` | 已创建 |
| `queued` | 排队中 |
| `running` | 执行中 |
| `finished` | 已完成 |
| `failed` | 失败 |
| `cancelled` | 已取消 |

## 10. 外包团队注意事项

1. 不要调用旧接口 `/api/task`、`/api/upload`、`/api/files`，新页面统一使用 `/api/v1`。
2. 不要直接访问 RAGFlow、MySQL、Redis 或模型接口。
3. 所有请求都要带 `X-Workspace-Id` 和 `X-User-Id`，用于开发阶段空间隔离。
4. 长任务必须通过任务接口创建，再通过状态接口和 WebSocket 展示进度。
5. 页面要处理 `queued`、`running`、`finished`、`failed`、`cancelled` 五类状态。
6. 文件上传后不要假设已经入库，必须展示后端返回的状态。
7. 后续鉴权、权限、限流和审计会继续加在 `/api/v1` 中间层。
