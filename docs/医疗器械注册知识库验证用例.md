# 医疗器械注册知识库验证用例

## 1. 使用说明

本验证用例用于测试医疗器械注册知识库的导入、检索、问答、引用和用户隔离能力。

建议测试顺序：

1. 先用 RAGFlow `retrieve` 直接测试知识库召回。
2. 再用 `/api/v1/tasks/qa` 测试智能体问答。
3. 最后测试用户上传私有文件隔离。

验证时重点观察：

1. 是否召回正确知识库。
2. 是否引用正确文档。
3. 是否能给出明确来源。
4. 无依据时是否拒绝编造。
5. 用户私有文件是否不会串到其他用户。

## 2. RAGFlow 召回验证 Case

### Case RAG-001：临床评价推荐路径

问题：

```text
医疗器械临床评价推荐路径如何确定？
```

期望命中知识库：

```text
mdr_public_clinical_eval
```

期望召回内容：

```text
《医疗器械分类目录》相关产品临床评价推荐路径
决策是否开展医疗器械临床试验技术指导原则
同品种医疗器械
临床试验
```

通过标准：

1. 召回结果包含临床评价推荐路径相关通告或说明。
2. 能区分“临床试验”和“同品种”路径。
3. 相似度结果不为空。

### Case RAG-002：同品种临床评价

问题：

```text
标注为同品种的医疗器械，注册时是否一定不需要临床试验？
```

期望命中知识库：

```text
mdr_public_clinical_eval
mdr_public_common_questions
```

期望回答要点：

```text
不一定。
如果申报产品与同品种医疗器械相比存在显著差异，可能仍需要临床试验资料。
应结合适用范围、技术特征、生物学特性、已有临床数据等判断。
```

通过标准：

1. 不应简单回答“一定不需要”。
2. 应引用临床评价路径或相关指导原则。

### Case RAG-003：指导原则检索

问题：

```text
医疗器械注册技术审查指导原则主要用于解决什么问题？
```

期望命中知识库：

```text
mdr_public_guidelines
```

期望回答要点：

```text
指导注册申请人准备申报资料。
明确技术审评关注点。
帮助统一审评尺度。
不能替代具体法规和正式审评结论。
```

通过标准：

1. 能召回指导原则文本库中的文档。
2. 回答不能泛泛而谈，需结合注册申报和技术审评。

### Case RAG-004：共性问题检索

问题：

```text
医疗器械注册申报中常见的补正问题有哪些？
```

期望命中知识库：

```text
mdr_public_common_questions
```

期望回答要点：

```text
资料完整性
适用标准
产品技术要求
临床评价
说明书标签
检验报告
风险管理资料
```

通过标准：

1. 能从共性问题或交流园地召回相关内容。
2. 如果当前样本数据不足，应明确说明“当前知识库样本不足”。

### Case RAG-005：审评报告检索

问题：

```text
审评报告通常可以帮助我们分析哪些注册审评关注点？
```

期望命中知识库：

```text
mdr_public_review_reports
```

期望回答要点：

```text
产品适用范围
主要技术指标
临床评价依据
风险收益判断
补充资料关注点
审评结论
```

通过标准：

1. 能召回审评报告类文档。
2. 回答应强调审评报告可作为参考，不替代正式法规判断。

### Case RAG-006：征求意见稿风险提示

问题：

```text
征求意见稿中的要求能否直接作为注册申报的强制依据？
```

期望命中知识库：

```text
mdr_public_draft_comments
```

期望回答要点：

```text
不能直接作为正式强制依据。
征求意见稿代表政策或技术要求趋势。
正式申报仍应以现行有效法规、公告、指导原则为准。
```

通过标准：

1. 回答必须提示“征求意见稿不是正式生效文件”。
2. 不应把征求意见稿当成现行法规直接引用。

### Case RAG-007：公告类资料检索

问题：

```text
医疗器械公告类文件一般能提供哪些注册信息？
```

期望命中知识库：

```text
mdr_public_regulatory_notices
```

期望回答要点：

```text
公告编号
发布日期
产品或事项范围
附件文件
适用对象
执行时间
```

通过标准：

1. 能召回公告或批件发布类文档。
2. 回答应区分公告正文和附件内容。

## 3. 智能体问答验证 Case

### Case AGENT-001：综合问答

问题：

```text
请说明医疗器械首次注册时，如何判断是否需要开展临床试验，并列出判断依据。
```

期望行为：

1. 优先调用 RAGFlow 知识库。
2. 检索临床评价推荐路径和临床试验决策相关资料。
3. 给出分步骤判断逻辑。
4. 附带引用来源。

通过标准：

1. 回答不能只给结论。
2. 需要说明“同品种”“临床试验”“高风险医疗器械”等关键判断点。

### Case AGENT-002：报告生成

问题：

```text
生成一份《医疗器械临床评价路径判断要点》的 Markdown 报告，要求包含适用场景、判断步骤、资料清单和风险提示。
```

期望行为：

1. 生成 Markdown 报告。
2. 报告结构清晰。
3. 包含引用或来源说明。

通过标准：

1. `/api/v1/tasks/{task_id}/result` 能看到生成文件。
2. 文件位于当前任务的输出目录。

### Case AGENT-003：无依据问题

问题：

```text
某个未提供名称和注册证编号的产品，是否一定可以免临床？
```

期望行为：

1. 系统应说明信息不足。
2. 不应直接给出“一定可以免临床”的结论。
3. 应提示需要产品分类、预期用途、技术特征、同品种对比等信息。

通过标准：

1. 回答有不确定性提示。
2. 不编造产品信息。

## 4. 用户私有文件隔离验证 Case

### Case ISO-001：Alice 上传文件，Alice 可见

请求头：

```text
X-Workspace-Id: reg-team
X-User-Id: alice
```

操作：

```text
POST /api/v1/documents/upload
GET /api/v1/documents?thread_id=iso-test-001
```

通过标准：

1. Alice 能看到自己上传的文件。
2. 文件路径包含 `workspaces/reg-team/users/alice/session_iso-test-001`。

### Case ISO-002：Alice 上传文件，Bob 不可见

Alice 上传请求头：

```text
X-Workspace-Id: reg-team
X-User-Id: alice
```

Bob 查询请求头：

```text
X-Workspace-Id: reg-team
X-User-Id: bob
```

操作：

```text
GET /api/v1/documents?thread_id=iso-test-001
```

通过标准：

1. Bob 查询结果为空。
2. Bob 无法通过 `doc_id` 查询到 Alice 文件。

### Case ISO-003：同一用户不同任务隔离

请求头：

```text
X-Workspace-Id: reg-team
X-User-Id: alice
```

操作：

1. 上传文件到 `thread_id=task-a`。
2. 上传文件到 `thread_id=task-b`。
3. 分别查询两个 `thread_id`。

通过标准：

1. `task-a` 只看到自己的文件。
2. `task-b` 只看到自己的文件。

### Case ISO-004：智能体只读取当前用户文件

请求头：

```text
X-Workspace-Id: reg-team
X-User-Id: alice
```

操作：

1. Alice 上传一个包含特殊内容的测试文件到 `thread_id=agent-private-001`。
2. 创建同一 `thread_id` 的问答任务。
3. 让智能体总结上传文件。

通过标准：

1. 智能体能读取 Alice 当前任务上传的文件。
2. 不会读取 Bob 或其他任务文件。

## 5. API 联调验证 Case

### Case API-001：健康检查

接口：

```text
GET /api/v1/health
```

通过标准：

```json
{
  "success": true,
  "code": "OK"
}
```

### Case API-002：知识库列表

接口：

```text
GET /api/v1/datasets
```

通过标准：

返回结果包含：

```text
mdr_public_guidelines
mdr_public_review_reports
mdr_public_common_questions
mdr_public_clinical_eval
mdr_public_draft_comments
mdr_public_regulatory_notices
```

### Case API-003：创建问答任务

接口：

```text
POST /api/v1/tasks/qa
```

请求头：

```text
X-Workspace-Id: reg-team
X-User-Id: alice
```

请求体：

```json
{
  "query": "医疗器械临床评价推荐路径如何确定？",
  "thread_id": "qa-case-001",
  "dataset_ids": [],
  "metadata": {}
}
```

通过标准：

1. 返回 `task_id = qa-case-001`。
2. 返回 `workspace_id = reg-team`。
3. 返回 `user_id = alice`。
4. 状态进入 `queued` 或 `running`。

### Case API-004：查询任务状态

接口：

```text
GET /api/v1/tasks/qa-case-001
```

请求头：

```text
X-Workspace-Id: reg-team
X-User-Id: alice
```

通过标准：

1. 能查到任务。
2. 换成 `X-User-Id: bob` 后查不到该任务。

## 6. PowerShell 快速测试命令

### 6.1 RAGFlow 检索测试

```powershell
cd D:\workspace\agent\medireg-agents

uv run python -c "from app.tools.ragflow_tools import ragflow_client; d=[x for x in ragflow_client.list_datasets(page=1,page_size=20) if x.name=='mdr_public_clinical_eval'][0]; chunks=ragflow_client.retrieve(dataset_ids=[d.id], question='医疗器械临床评价推荐路径如何确定？', page_size=3, top_k=20); [print('---\n', c.document_name, c.similarity, c.content[:300]) for c in chunks]"
```

### 6.2 API 健康检查

```powershell
Invoke-RestMethod http://localhost:8000/api/v1/health
```

### 6.3 创建问答任务

```powershell
Invoke-RestMethod `
  -Method Post `
  -Uri http://localhost:8000/api/v1/tasks/qa `
  -Headers @{
    "X-Workspace-Id" = "reg-team"
    "X-User-Id" = "alice"
  } `
  -ContentType "application/json" `
  -Body '{"query":"医疗器械临床评价推荐路径如何确定？","thread_id":"qa-case-001","dataset_ids":[],"metadata":{}}'
```

### 6.4 查询任务状态

```powershell
Invoke-RestMethod `
  -Uri http://localhost:8000/api/v1/tasks/qa-case-001 `
  -Headers @{
    "X-Workspace-Id" = "reg-team"
    "X-User-Id" = "alice"
  }
```

### 6.5 上传用户私有文件

```powershell
Invoke-RestMethod `
  -Method Post `
  -Uri http://localhost:8000/api/v1/documents/upload `
  -Headers @{
    "X-Workspace-Id" = "reg-team"
    "X-User-Id" = "alice"
  } `
  -Form @{
    thread_id = "iso-test-001"
    files = Get-Item "D:\test\a.txt"
  }
```

### 6.6 查询用户私有文件

```powershell
Invoke-RestMethod `
  -Uri "http://localhost:8000/api/v1/documents?thread_id=iso-test-001" `
  -Headers @{
    "X-Workspace-Id" = "reg-team"
    "X-User-Id" = "alice"
  }
```
